# Исходники сайта

HTML-страницы в корне репозитория генерируются, на каждой странице есть оба языка. Для поисковиков генератор также создаёт копии в `ru/` с русским языком по умолчанию (свои заголовки, описания и `hreflang`). Посетитель, пришедший из поиска на `/ru/...`, видит обычный адрес: скрипт убирает `/ru` из адресной строки без перезагрузки и запоминает русский язык. Правьте данные здесь и не редактируйте HTML вручную: следующая сборка перезапишет правки. GitHub Pages не публикует папки, имя которых начинается с `_`, поэтому `_src/` на сайт не попадает.

```
node _src/build.mjs     # собрать сайт (нужен только Node.js, зависимостей нет)
node _src/serve.mjs     # посмотреть локально на http://127.0.0.1:8080
python _src/images.py   # сделать WebP из новых PNG-скриншотов (нужен Pillow)
```

## Новая сборка

В `data/builds.json` обновите `number`, `date`, блок `changes` и для каждого языка в `images` поля `file`, `btih`, `size` (в байтах) и `sums`. Предыдущую сборку добавьте в начало `releases` в `data/archive.json`: файлы на dl3 остаются на месте, ссылки не меняются.

SHA-256 указывается в поле `sums.sha256`. Если оно заполнено, строка появляется на странице. Посчитать сумму:

```powershell
(Get-FileHash .\файл.iso -Algorithm SHA256).Hash.ToLower()
```

Размер файла на сервере можно узнать так:

```
curl -sI "https://dl3.somov.org/файл.iso" | findstr /i content-length
```

При создании нового `.torrent` указывайте те же трекеры, что и в `TRACKERS` в `build.mjs`, иначе раздачу можно будет найти только через DHT.

## Счётчик скачиваний

Скачивания `.iso` и `.torrent` считает сам сервер dl3: nginx отправляет счётчику отметку о каждом скачивании, откуда бы ни пришла ссылка (сайт, Telegram). Magnet-ссылки до сервера не доходят, поэтому их считает сайт по нажатию кнопки. Файлы `.torrent`, прикреплённые прямо в Telegram, посчитать нельзя. Код лежит в `counter/`, на сервере он установлен в `/opt/somov-counter`, данные хранятся в `/var/lib/private/somov-counter/counts.db`. С одного IP каждый образ считается раз в календарные сутки (по Вьетнаму, с полуночи до полуночи; так же считает страница статистики), каким бы способом его ни взяли (ISO, торрент и magnet одного образа считаются вместе); разные образы, Ghost Spectre и файлы твиков считаются отдельно. IP посетителей не хранятся: сервис помнит, кого уже засчитал, по солёному хэшу IP и действия. При остановке (обновление, перезагрузка сервера) он сохраняет хэши в `/var/lib/somov-counter/seen.json`, при запуске читает и удаляет файл, так что перезапуски никого не засчитывают дважды. Нажатия с IP владельца не считаются.

Просмотры страниц: каждая страница при открытии отправляет `?page=<путь>&kind=view`, один IP считается раз в сутки на каждую страницу. Копии `/ru` и адреса `-en`/`-ru` сборок считаются одной страницей, 404 не считается. Владелец видит строку под шапкой: сегодня, 7 дней, 30 дней, всего. Суточные строки в базе хранятся 30 дней.

Переходы в Telegram: любая ссылка на канал с `data-tg-placement` (шапка, подвал, карточки `home` и `build`) отправляет `?tg=<место>&kind=click`. Общая цифра — один IP раз в сутки на весь сайт, по месту — раз в сутки на место. Владелец видит под карточками «всего · отсюда».

Открытия чата: каждая ссылка на чат с `data-chat-placement` (подвал `footer`, страница сборки `build`, твики `tweak`, архив `archive`, низ настроек `settings`, пустой поиск `settings-empty`; список — `CHAT_PLACES` в `build.mjs`) отправляет `?chat=<место>&kind=click`. Счёт как у Telegram: общий — один IP раз в сутки, по месту — раз в сутки на место. Владелец видит под каждой такой ссылкой «Открыли чат: всего · отсюда». Новое место нужно добавить в `CHAT_PLACES`, иначе счётчик его не примет.

Подробная история: логи nginx на dl3 хранятся год (`/etc/logrotate.d/nginx`, `rotate 365`): IP, время, адрес, код ответа, referrer, User-Agent. Смотреть в читаемом виде: на dl3 `somov-log <IP | часть адреса | today> [--bots] [--days N]` или `SiteLog …` в PowerShell.

Два счёта: уникальный (один человек — раз в сутки на каждую вещь; его можно будет сделать публичным) и «всего» (каждое действие, видно только владельцу, в базе это виды `all:<вид>`, а у страниц `hits` и строки `hday:`). Во «всего» скачивание считается по началу загрузки (без Range или с Range от нулевого байта: nginx передаёт счётчику `X-Original-Range`), не больше 30 действий одного IP с одной вещью в сутки. Роботы (bot, crawl, spider, preview, Dalvik…) не считаются нигде: nginx передаёт `X-Original-UA`. Роботы под видом браузера из сетей поисковиков и соцсетей узнаются по имени адреса (обратный DNS, раз в сутки на адрес): `spider.yandex.com`, `fbsv.net`, `googlebot.com` и др. (`ROBOT_HOSTS`). Облачные серверы (Amazon, Google Cloud, Azure) по одному считаются (это может быть VPN), но 3 разных облачных адреса с одним браузером на одной странице за минуту — пачка роботов: их просмотры снимаются, и сутки они не считаются. Роботы, которые притворяются браузером, ловятся по поведению: если IP без перехода с сайта (nginx передаёт `X-Original-Referer`) запросил больше 10 разных файлов за 10 секунд, его скачивания за эти секунды вычитаются, и сутки он не считается (`BURST_FILES`, `BURST_WINDOW` в `server.py`). Пересчитать всё по логам nginx: на dl3 `python3 /root/rebuild_counts.py` (без `--write` только показывает), перед записью остановите службу и сделайте копию базы.

Скачивания твиков копятся по твику, а не по имени файла: в `counter-keys.json` есть таблица «файл → твик», счётчик хранит её в базе навсегда, поэтому новая версия программы продолжает счёт, а старый файл по старой ссылке засчитывается тому же твику. Сборки (свои и Ghost Spectre) считаются по файлу: новая сборка начинает с нуля.

Защита от мусора: при сборке генератор пишет `counter-keys.json` (все страницы, id твиков и места ссылок на Telegram). Счётчик раз в 10 минут скачивает его с somov.org и принимает только эти значения; копия хранится рядом с базой на случай, если сайт недоступен. Новый твик начинает считаться в течение 10 минут после `GitPush`. В nginx на `/api/` стоит ограничение 10 запросов в секунду с одного IP (`deploy.py`).

Запросы с самого dl3 (`89.110.97.213`, `127.0.0.1`, `::1`: проверки и тесты на сервере) не считаются никогда; список задаётся `SELF_IPS` в `server.py` или переменной окружения `SELF_IPS`.

Убрать из счётчика свои заходы с VPN: на dl3 `somov-forget-ip <IP>` (или `SiteForgetIp` в PowerShell).

Цифры на сайте видны только с IP из `/etc/somov-counter.env`. С этих же IP визиты не попадают в Google Analytics: перед отправкой просмотра страница спрашивает счётчик, IP ли это владельца (если счётчик не ответил за 2,5 с, просмотр отправляется). Кроме того, Analytics можно отключить на одном устройстве, открыв сайт с `/?noga` (вернуть: `/?ga`); это работает с любого IP.

Телефон и другие устройства с меняющимся IP: один раз откройте на устройстве `https://somov.org/?owner=<ключ>` (ключ — `OWNER_TOKENS` в `/etc/somov-counter.env` на dl3). Браузер запомнит ключ и сразу уберёт его из адреса; с любого интернета статистика будет видна, а ваши просмотры и нажатия не будут считаться. Скачивания файлов сервер видит без ключа, их можно убрать через `SiteForgetIp`. Забыть ключ на устройстве: `/?owner=off`. Сменить ключ для всех устройств: поменяйте `OWNER_TOKENS` и выполните `systemctl restart somov-counter`.

Если ваш IP сменился, выполните на dl3 (несколько адресов указываются через запятую), это обновит и счётчик, и исключение в Analytics:

```
echo "OWNER_IPS=новый.ip" > /etc/somov-counter.env && systemctl restart somov-counter
```

Чтобы показать цифры всем, нужно в `server.py` отдавать статистику без проверки IP и обновить файл на сервере.

## Страница статистики

Личная страница со всей статистикой: **https://dl3.somov.org/stats/** (только для владельца: домашний IP из `OWNER_IPS`, на других устройствах один раз открыть `https://dl3.somov.org/stats/?key=<OWNER_TOKENS>` — устройство запомнит на год; остальным — «Страница не найдена»). Служба `somov-stats` на dl3 (`/opt/somov-stats`, код в `stats/`) раз в 5 минут читает логи nginx и считает по дням: посещения, просмотры, скачивания сборок (ISO / торрент / magnet, с сайта или по прямой ссылке), страны с флагами (локальная база DB-IP, раз в месяц обновляется сама), источники (реклама Директа, Яндекс, Google, Telegram, прямые заходы — сайт передаёт их с просмотром страницы с 12.11.2026), устройства, твики, переходы в Telegram и чат, ленту последних действий. Строки статистики на сайте (видны только владельцу) берут цифры отсюда же: счётчик на запрос `/api/stats` отдаёт числа страницы статистики (`/internal/counts`, только изнутри dl3), поэтому сайт и страница всегда показывают одно и то же; если служба статистики не отвечает, счётчик отдаёт свои суммы. Цифры обновляются раз в минуту. Правила те же, что у счётчика: человек раз в календарные сутки (Вьетнам), владелец и роботы (по имени браузера, имени адреса, пачке облачных адресов, слишком быстрым скачиваниям) не считаются, IP не хранятся. Считается с запуска счётчика, 7 ноября 2026.

## Чат

Кнопка «Чат» в подвале (или адрес с `#chat`) открывает окно переписки. Сообщения принимает служба на VpsDl (`dl.somov.org/api/chat/`, код в `chat/`, на сервере `/opt/somov-chat`, служба `somov-chat`, база `/var/lib/private/somov-chat/chat.db`). Бот @somov_chat_bot присылает каждое сообщение в Telegram с номером переписки, контактом и страницей. Чтобы ответить, нажмите «Ответить» на сообщении посетителя: ответ появится у него в окне, на кнопке «Чат» загорится точка. Токен бота хранится в `/etc/somov-chat.env` на VpsDl. Ограничения: 6 сообщений в минуту и 40 в сутки с одного IP, 400 в сутки всего; IP не сохраняются. Переписка, где никто не писал год, удаляется.

Файлы: посетитель прикрепляет их скрепкой, вставляет скриншот через Ctrl+V или перетаскивает в окно (до 10 МБ, не больше 60 МБ в сутки с одного IP). Фото приходят в Telegram как фото, остальное — файлом. Ответить можно фото или файлом до 20 МБ. Файлы лежат в `/var/lib/private/somov-chat/files` (всего не больше 2 ГБ), и открыть их может только та переписка, к которой они относятся. Всё, кроме картинок, отдаётся только на скачивание.

Уведомления посетителю: после первого сообщения в чате появляется кнопка «🔔 Сообщить, когда придёт ответ». Если человек разрешит уведомления, браузер регистрирует `sw.js` (лежит в корне сайта, ничего не кэширует), и на каждый ваш ответ служба отправляет ему зашифрованное уведомление Web Push. Оно приходит, даже если сайт закрыт, а по нажатию открывает чат. Ключи для подписи уведомлений (`VAPID_PRIVATE`, `VAPID_PUBLIC`) лежат в `/etc/somov-chat.env`; если их сменить, старые подписки перестанут работать. На iPhone уведомления работают, только если сайт добавлен на экран «Домой».

Письма: если посетитель оставил почту, служба один раз отправляет ему письмо «Подтвердите почту» (в нём же сказано, что вопрос получен) с кнопкой подтверждения. Только после подтверждения ваши ответы из Telegram дублируются на эту почту (фото и файлы — вложением); до этого бот предупреждает «❔ почта не подтверждена — ответ только в чате», а в уведомлениях у контакта стоит «(не подтверждена)». Подтверждается именно тот адрес, на который ушло письмо, поэтому чужую почту в поле контакта вписать бесполезно. Письма уходят от `me@somov.org` через Gmail SMTP (`GMAIL_USER` и `GMAIL_APP_PASSWORD` — пароль приложения Google — в `/etc/somov-chat.env`). Письмо «мы получили» никогда не содержит текста посетителя, а с одного IP их не больше 3 в сутки (всего 50), чтобы через чат нельзя было слать письма на чужие адреса. Ответы на письма приходят на `me@somov.org`.

Отписка: в каждом письме посетителю есть ссылка «Отписаться» (и заголовок `List-Unsubscribe`, по которому Gmail показывает свою кнопку). Ссылка открывает страницу с кнопкой (сама ссылка ничего не делает, чтобы её не «нажимали» антивирусы); после отписки письма этой переписке не уходят, бот сообщает «📭 #N отписался». Если посетитель впишет почту заново, письма снова включаются.

Почта на `me@somov.org` в Telegram: раз в минуту служба читает входящие Gmail (IMAP, только чтение: письма не помечаются прочитанными и не трогаются) и приносит каждое новое письмо на `me@somov.org` в Telegram как переписку «📨 #N · письмо» с вложениями. Ответ в Telegram через «Ответить» уходит отправителю письмом от `me@somov.org` в ту же цепочку («Re: тема»). Не приносятся только рассылки (заголовки `List-Unsubscribe`/`List-Id`/`Precedence: bulk`), автоответы (`Auto-Submitted`) и адреса вида `no-reply@`, `notifications@`, `mailer-daemon@`; они остаются в Gmail. Если письмо пришло с адреса, который посетитель чата **подтвердил** по ссылке из письма, оно попадает в его переписку с тем же номером #N и видно ему в чате на сайте; письма с любых других адресов (в том числе с неподтверждённого адреса из поля контакта) всегда открывают отдельную «почтовую» переписку и в окно чата не попадают. Копий сообщений из чата в Gmail нет: всё приходит в Telegram.

Флаг страны в уведомлении: служба раз в месяц скачивает бесплатную базу стран DB-IP (`geoip.db` рядом с базой чата) и ищет в ней IP посетителя у себя. Наружу IP не уходит, в базе чата хранится только код страны.

Обновить службу: скопировать `chat/server.py` в `/opt/somov-chat/` и выполнить `systemctl restart somov-chat`. Маршрут в nginx описан в `chat/nginx-chat.conf`.

## Бэкап

Каждую ночь оба сервера сами отправляют свои данные в закрытый репозиторий GitLab `as-backup/somov-data` (туда же, где бэкапы ботов). Скрипт один: `backup/somov-backup.sh`, на серверах — `/usr/local/sbin/somov-backup.sh`, журнал — `/var/log/somov-backup.log`.

- VpsDl, 04:10 по Москве: переписки чата → `vpsdl/chat.sql`, файлы из чата → `vpsdl/files/`.
- dl3, 04:20: статистика счётчика → `dl3/counts.sql`, `dl3/counter-keys.json`.

Базы лежат SQL-текстом, поэтому git хранит только изменения за день, и можно взять состояние на любой день (`git log`, `git checkout <коммит> -- путь`). Если за день ничего не изменилось, коммита нет. Доступ к GitLab — обычный ключ сервера (`/root/.ssh/id_rsa`).

Секреты тоже в бэкапе, но зашифрованы git-crypt: `vpsdl/secrets/somov-chat.env` (токен бота, ID владельца, пароль приложения Gmail, ключи уведомлений `VAPID_*`) и `dl3/secrets/somov-counter.env` (IP и ключи владельца). В GitLab это нечитаемые байты; расшифровать можно только ключом `git-crypt-key.bin` — он лежит на обоих серверах в `/root/.ssh/` и копией у владельца в менеджере паролей. Без ключа секреты из бэкапа не восстановить. Скрипт не отправит секреты, если шифрование на сервере не включено. База стран `geoip.db` не нужна: служба скачает её сама.

Расшифровать бэкап на новом сервере: `git clone git@gitlab.com:as-backup/somov-data.git && cd somov-data && git-crypt unlock /путь/git-crypt-key.bin`. Ключ из менеджера паролей (если сохранён текстом base64): `echo '<текст>' | base64 -d > git-crypt-key.bin`.

Восстановление (пример для чата на VpsDl; для счётчика то же с `somov-counter`, `counts.db` и `dl3/counts.sql`):

```
systemctl stop somov-chat
cd /root/somov-backup && git pull
mv /var/lib/private/somov-chat/chat.db /root/chat.db.old
sqlite3 /var/lib/private/somov-chat/chat.db < vpsdl/chat.sql     # или: python3 -c "import sqlite3,sys; sqlite3.connect(sys.argv[1]).executescript(open(sys.argv[2]).read())" <база> <sql>
cp -a vpsdl/files/. /var/lib/private/somov-chat/files/
chown -R somov-chat: /var/lib/private/somov-chat 2>/dev/null; systemctl start somov-chat
```

## Снег

Зимний эффект на всём сайте (`assets/snow.js`): снежинки разного размера на медленном ветру, сугроб внизу экрана, тонкий слой на верхних краях крупных карточек, курсор раскидывает снег; поверх шапки и внутри карточек снега нет, клики проходят сквозь него, в фоновой вкладке он на паузе.

**Сам каждый год с 1 декабря по 31 января** (по дате посетителя; даты — `from` / `to` в `data/snow.json`). Вне сезона нет ничего: ни снега, ни кнопки, `?snow` не работает. Вручную, потом `GitPush`:

```
node _src/snow.mjs auto   # по датам, каждый год (так и стоит)
node _src/snow.mjs on     # прямо сейчас и всегда, не глядя на дату
node _src/snow.mjs off    # никогда: файл снега даже не подключается
node _src/snow.mjs        # показать, как сейчас
```

В сезон посетитель может выключить снег круглой кнопкой-снежинкой в шапке, слева от EN/RU (запоминается; один раз за вкладку, через 2,5 с после того как снег пришёл, кнопка мягко «вздыхает»); у кого в системе выключены анимации — снег сам не включается; `?snow=0` / `?snow=1` — выключить / включить на это посещение.

## Страница поддержки

Способы поддержки на `/support` задаются в `DONATE` в `build.mjs`. `DONATE.tribute` — веб-ссылка на донаты Tribute (карты любых стран), пустая строка убирает карточку. Когда появится страница Patreon, впишите её адрес в `DONATE.patreon`: на странице появится главная кнопка. Если меняется адрес USDT, обновите его и в `_src/qr.py`, затем запустите `python _src/qr.py` (нужен `pip install segno`), чтобы перегенерировать QR-код.

## Другие данные

- `data/ghost-spectre.json`: сборки Ghost Spectre.
- `data/settings.json`: категории и пункты страницы настроек. Для каждого пункта генератор создаёт отдельную страницу `/tweaks/<id>` (и русскую копию): `id` становится адресом, поэтому не меняйте его у существующих пунктов. Инструкция «Как применить» строится по типу файла и меткам `admin` и `reboot`.
- `data/featured.json`: первый раздел страницы настроек, со своей кнопкой в ряду категорий и поиском. `heading` — название раздела и кнопки, `title` и `desc` — название и описание пункта, `link` — ссылка (пустой `url` скрывает её), `file` — имя файла на dl3 или полный адрес `https://...` (пустая строка убирает кнопку «Скачать»). `"show": false` скрывает раздел целиком.
- Новые скриншоты кладите в `images/windows-<версия>-<язык>/` как `1.png`...`6.png`, затем запускайте `images.py`.
